# Admin and Public Contracts

Use this spec when adding API wire types or generated route inventory in
`crates/nako-api`.

## Scenario: API Contract Change

### 1. Scope / Trigger

- Trigger: new route, response/request DTO, public SDK method, admin contract
  route, error code, or API-version behavior.
- Evidence: `src/admin.rs`, `src/admin/*.rs`, `src/admin_contract.rs`,
  `src/openapi.rs`, `src/sdk.rs`, `apps/admin-web/src/adminApi/generated/contract.ts`,
  and `docs/api/HTTP_API.md`.
- Authority: ADR 0023, ADR 0025, ADR 0027, ADR 0053.

### 2. Signatures

- Public API DTOs and SDK generation live under `public_client`, `openapi`, and
  `sdk` modules.
- Admin DTOs live under `admin.rs` and `admin/*` modules.
- Admin route constants are generated by `admin_contract.rs` into
  `NAKO_ADMIN_ROUTES`.
- Admin API version is `ADMIN_API_VERSION: &str = "v1"`.
- Public API response version header is `x-nako-api-version`.

### 3. Contracts

- Public Client API is generated from `nako-api`, not from Axum route handlers.
- Admin `/admin/v1/*` routes are intentionally separate from the Public Client
  inventory and TypeScript SDK in `sdk/typescript`.
- Admin Web consumes its local generated contract file:
  `apps/admin-web/src/adminApi/generated/contract.ts`.
- Generated admin contract output starts with the generator command and exports:
  `NAKO_ADMIN_API_VERSION`, `NAKO_ADMIN_ROUTES`, route-key types, and DTO types.
- New admin responses should include `admin_api_version` when comparable
  existing admin responses do so.
- DTOs should use serde-compatible snake_case wire fields matching existing
  `nako_api::admin` and `nako_api::public_client` structures.

### 4. Validation & Error Matrix

| Change | Required validation |
|--------|---------------------|
| Public route/DTO | OpenAPI and SDK generator tests in `nako-api` |
| Public SDK method | TypeScript SDK generated output check and committed package drift check |
| Admin route/DTO used by Admin Web | `admin_contract` tests and regenerated `apps/admin-web` contract |
| Admin route accidentally added to public inventory | `nako-api` tests must reject `/admin` and `/admin/v1` in public outputs |
| Sensitive/raw field added | Redaction/leakage tests must reject local paths, secrets, raw tokens, raw provider cache, jobs, addons, webhooks, automation, and storage internals as appropriate |

### 5. Good / Base / Bad Cases

- Good: add a DTO in the correct `nako-api` admin/public module, add route
  inventory in the matching generator, update server mapping, regenerate the
  Admin Web contract if needed, and add focused generator tests.
- Base: admin-only diagnostics route updates only `nako_api::admin`,
  `admin_contract.rs`, `nako-server`, and Admin Web local contract.
- Bad: putting Admin `/admin/v1/*` into the Public Client SDK or hand-editing
  `apps/admin-web/src/adminApi/generated/contract.ts`.

### 6. Tests Required

- Focused API contract:
  `cargo nextest run -p nako-api admin_contract --no-fail-fast`
- Public SDK/OpenAPI change:
  `cargo nextest run -p nako-api --no-fail-fast`
  and `cargo check -p nako-api --examples`
- Admin Web contract refresh:
  `npm run generate:admin-api --prefix apps/admin-web`
  followed by Admin Web check/test gates.

### 7. Wrong vs Correct

#### Wrong

```typescript
// apps/admin-web/src/adminApi/generated/contract.ts
export const NAKO_ADMIN_ROUTES = { newRoute: "/admin/v1/new-route" };
```

#### Correct

```bash
cargo run -p nako-api --example emit-admin-typescript-contract -- --output apps/admin-web/src/adminApi/generated/contract.ts
```

Generated contract files are artifacts from `nako-api`; edit the generator and
DTO source, then regenerate.
