# AAD-070 — Admin Addon API and DTO shielding

Date: 2026-05-21
Owner: codex

## Summary

Migrated Addon registration/list/detail management to the Admin API boundary.
The old root `/addons` management surface is intentionally removed because Nako
has no compatibility obligation yet.

## Implementation

- Removed legacy `AddonRegistrationResponse` and `AddonRegistrationsResponse`
  DTOs that exposed `AddonRegistrationRecord` directly.
- Added/used Admin Addon summary/detail response DTOs in `nako-api`.
- Mounted registration/list/detail only under `/admin/v1/addons`.
- Kept runtime Addon routes under `/addon/v1/*` and token/grant Admin routes
  under `/admin/v1/addons/{addon_id}`.
- Updated HTTP tests to use Admin DTOs and assert:
  - root `/addons` registration/list/detail returns `404`;
  - Admin create/detail responses omit `manifest_json`;
  - list responses return summaries rather than persistence records.
- Updated HTTP API, Addon author guide, and Admin Web Console API matrix docs.
