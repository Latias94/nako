# AAD-090 Journal — Addon Persistence Parity

Date: 2026-05-21

## Intent

Verify and repair SQLite/PostgreSQL parity for the Addon persistence slice
touched by fingerprinted Addon Side Effect idempotency.

## Decision

Taru has no deployed users yet, so the correct boundary is a clean schema, not
a compatibility migration. `request_fingerprint` is a required property of an
Addon Side Effect record and should be present in the base SQLite/PostgreSQL
schemas.

## Changes

- Added `request_fingerprint TEXT NOT NULL` directly to SQLite migration
  `0022_addon_side_effects.sql`.
- Added `request_fingerprint text NOT NULL` directly to PostgreSQL proof schema
  `migrations/postgres/0001_contract_jobs.sql`.
- Removed the temporary `0031` Addon Side Effect fingerprint migration from the
  SQLite migration list.
- Removed nullable row-decoding fallback for historical fingerprint-less rows.
- Kept repository insert behavior deriving the deterministic fingerprint from
  permission, library, target, provenance JSON, and payload JSON.
- Added SQLite test evidence that the migrated column is non-null and that the
  persisted record round-trips the expected deterministic fingerprint.

## Validation

```text
cargo check -p taru-db --tests
cargo nextest run -p taru-db addon --no-fail-fast
rg -n "0031|addon_side_effect_request_fingerprint|request_fingerprint_idx|Option<String>.*request_fingerprint|request_fingerprint.*Option|ADD COLUMN request_fingerprint" crates/taru-db
cargo fmt --all -- --check
git diff --check
```

All commands passed on 2026-05-21. The `rg` cleanup check returned no matches.
`git diff --check` emitted only Git CRLF normalization warnings.

PostgreSQL opt-in contracts were not run because `TARU_TEST_POSTGRES_URL` was
not set.
