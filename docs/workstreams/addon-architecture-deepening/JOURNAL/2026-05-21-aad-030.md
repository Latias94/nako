# AAD-030 Journal — Request Fingerprint Idempotency

Date: 2026-05-21

## Intent

Make Addon Side Effect idempotency distinguish true replay from conflicting
same-key request reuse.

## Changes

- Added `AddonSideEffectRequestFingerprint` in `nako-core`.
- Persisted `request_fingerprint` on Addon Side Effect rows.
- Persisted the request fingerprint on Addon Side Effect rows.
- Updated PostgreSQL contract schema in
  `migrations/postgres/0001_contract_jobs.sql`.
- Updated `AddonSideEffectRuntime` so same Addon plus same idempotency key only
  replays when the request fingerprint matches; different permission, library,
  target, provenance, or payload returns `409 conflict`.
- Extended focused HTTP tests to prove same-key different-payload and
  different-provenance requests conflict without leaking raw request content.

AAD-090 later removed the temporary compatibility migration/fallback approach
and folded `request_fingerprint` into the clean SQLite/PostgreSQL base schemas
as `NOT NULL`, because Nako has no deployed users to migrate.

## Validation

```text
cargo check -p nako-core -p nako-db -p nako-server --tests
cargo nextest run -p nako-db addon --no-fail-fast
cargo nextest run -p nako-server addon_side_effect --no-fail-fast
cargo fmt --all -- --check
git diff --check
```

All commands passed on 2026-05-21.

PostgreSQL opt-in contracts were not run because `NAKO_TEST_POSTGRES_URL` was
not set.
