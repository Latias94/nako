# AAD-080 — Protocol/client crate boundary audit

Date: 2026-05-21
Owner: codex

## Deletion Test

Question: can `nako-addon-protocol` keep both wire contracts and the HTTP
caller helper without real Interface cost?

Result: no. Keeping the caller in the protocol crate made every Addon wire
contract consumer inherit `reqwest` and `async-trait`, even when the consumer
only needed manifests, envelopes, scopes, Protected Write payload DTOs, and
validation.

## Implementation

- Created `nako-addon-client` as a permissive `Apache-2.0` helper crate.
- Moved `AddonTransport`, `ReqwestAddonTransport`, `AddonHttpRequest`,
  `AddonHttpResponse`, `AddonClientError`, and `call_addon_resource` to
  `nako-addon-client`.
- Kept `nako-addon-protocol` focused on wire DTOs and validation.
- Removed `reqwest` and `async-trait` from `nako-addon-protocol` dependencies.
- Updated server reference-addon tests to import caller helpers from
  `nako-addon-client`.
- Updated ADR/docs to describe the protocol/client split.

## Validation
