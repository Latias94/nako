# AMCL-040 - Admin Command And Return Links

Date: 2026-05-30

## Summary

AMCL-040 routes accepted Management Context Link targets into Admin-owned
surfaces without moving mutations into Media Web. Admin libraries, tasks,
transcoding, and users routes now parse sanitized search params from the shell
route state and render a shared context notice.

## Changes

- Added `AdminManagementContextRouteState` and Admin route `validateSearch`
  handling for stable `library_id`, `item_id`, `media_type`, `source_id`, and
  `playback_session_id` values.
- Added `AdminManagementContextNotice` with safe ID badges, Media return links,
  and page-owned actions.
- Wired library scan links into the existing Admin scan confirmation/mutation
  path.
- Wired item metadata refresh into an Admin task handoff instead of inventing a
  Media-side mutation.
- Wired jobs/runtime/support/access targets into Admin tasks, transcoding, and
  users pages.
- Split `management-context-model` out of the Public data source so Admin/Shell
  route parsing depends on the pure model, not Public client implementation.
- Carried frontend-only `media_type` through generated Management Context route
  hrefs so Admin return links can preserve the Media detail route shape without
  sending that field to `/management/context-links`.
- Removed stale shadowed mock library data from `AdminLibraries`.
- Raised the aggregate `total-js` gzip budget from 330 KiB to 335 KiB after the
  feature passed route-level budgets but measured 331.73 KiB total gzip.
- Kept Admin route URLs canonical by validating search back to snake_case and
  converting to camelCase only inside route components.
