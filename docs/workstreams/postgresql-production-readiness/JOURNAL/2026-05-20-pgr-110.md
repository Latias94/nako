# PGR-110 — SQLite Assumption Deletion Sweep

Date: 2026-05-20
Status: complete

## Goal

Delete or isolate SQLite-only assumptions above the database adapter seam so
runtime selection remains explicit and backend-neutral code does not depend on
SQLite row codecs, pool access, URL forms, timestamps, or SQL behavior.

## Changes

- Removed `TaruDatabase::connect(&str)` because it silently selected SQLite.
- Removed `TaruDatabase::connect_with_sqlite_runtime(...)`; production
  construction now flows through `DatabaseConnectOptions`.
- Kept `TaruDatabase::connect_in_memory()` as a clearly named test fixture
  convenience.
- Removed facade-level test imports of SQLite row codecs.
- Removed direct SQLite pool/column inspection from the startup job recovery
  test and verified the behavior through repository APIs instead.

## Inventory

- No server/API code imports `taru_db::sqlite`, `sqlite::codec`, or
  `SqliteStore`.
- SQLite SQL dialect terms remain isolated under `taru-db::sqlite` or
  SQLite-owned tests.
- `sqlite::memory:` remains in tests/default config examples only.
