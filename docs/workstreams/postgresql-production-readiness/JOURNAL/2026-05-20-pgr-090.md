# 2026-05-20 — PGR-090 Managed Artwork PostgreSQL Parity Split

## Summary

Completed PGR-090 for the PostgreSQL Production Readiness workstream by
splitting Managed Artwork PostgreSQL parity into a named follow-on instead of
implementing partial parity in M62.

## Decision

Managed Artwork PostgreSQL parity does not belong in M62 closeout. It is now
tracked by `docs/workstreams/managed-artwork-postgresql-parity/`.

## Rationale

Managed Artwork is a large runtime subsystem, not a small repository tail. It
spans Addon Artwork Candidates, Managed Artwork Ingest, durable jobs, artifacts,
Selected Artwork publication, galleries, lifecycle cleanup, drift/remediation
diagnostics, thumbnail variants, artifact-store files, and redaction-sensitive
public/Admin serving.

`PostgresStore` does not implement `ArtworkCandidateRepository` or
`ManagedArtworkRepository`; forcing parity into PGR-090 would either expand M62
substantially or risk partial PostgreSQL runtime support. M62 remains truthful by
splitting this surface and requiring explicit runtime gating until the follow-on
proves parity.

## Changes

- Added `docs/workstreams/managed-artwork-postgresql-parity/` with design,
  task ledger, milestones, evidence gates, handoff, and machine-readable state.
- Marked PGR-090 complete in `postgresql-production-readiness/TODO.md`.
- Updated PGR workstream design/milestones/evidence/handoff to name the split
  and forbid partial PostgreSQL Managed Artwork enablement.
- Added the follow-on to `docs/workstreams/README.md`.
