# PGR-010 — Workstream Open

Date: 2026-05-20

## Scope

Open M62 PostgreSQL Production Readiness as a durable execution lane.

## Current-State Findings

- `NakoDatabase` is a facade, but its production implementation currently
  stores only a SQLite adapter.
- `PostgresStore` exists behind `#[cfg(test)]`.
- PostgreSQL currently proves Library, Job, and Job Lease behavior only.
- Server configuration still has a `database_url` shape centered on SQLite
  construction.
- Most existing `nako-db` behavior tests are SQLite-specific even when they
  exercise facade behavior.

## Decisions

- Start with backend contract-test matrix and runtime backend selection before
  broad SQL migration work.
- Keep SQLite as the default and always-on backend.
- Keep PostgreSQL opt-in until local/CI verification is repeatable.
- Use explicit backend kind/config instead of relying only on URL scheme
  guessing.

## Validation

- `git diff --check` to be run after docs are written.
