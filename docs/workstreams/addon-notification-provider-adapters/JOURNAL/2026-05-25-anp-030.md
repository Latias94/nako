# 2026-05-25 — ANP-030 First Provider Send Path

Task: ANP-030
Status: DONE

## Implementation

Implemented the first `http_webhook` provider send path in
`nako-notification-bridge`.

When `http_webhook` is enabled with a valid URL, the sidecar sends one fixed
JSON summary after accepting a valid `library.scanned` event envelope. The
payload includes event facts and sorted payload keys only. It does not include
raw event payload values or rendered message bodies.

Provider credentials remain sidecar-owned:

- target URL comes from `NAKO_NOTIFICATION_BRIDGE_HTTP_WEBHOOK_URL`;
- optional shared secret comes from
  `NAKO_NOTIFICATION_BRIDGE_HTTP_WEBHOOK_SHARED_SECRET`;
- optional secret header name comes from
  `NAKO_NOTIFICATION_BRIDGE_HTTP_WEBHOOK_SECRET_HEADER_NAME`;
- no provider URL or provider secret is stored by Nako core.

## Retry And Failure Mapping

- Provider `2xx`: event route returns a successful ACK with provider status
  `sent`.
- Provider `408`, `429`, `5xx`, or transport failure: sidecar returns safe
  retryable failure `503`.
- Other provider `4xx`: sidecar returns safe non-retryable failure `424`.
- No sidecar background queue or provider attempt history was added.
