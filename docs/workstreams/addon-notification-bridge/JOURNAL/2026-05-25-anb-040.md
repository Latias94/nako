# ANB-040 — Provider Split Decision

Status: DONE
Date: 2026-05-25

## Decision

Do not implement a real notification provider inside the ACK-only notification
bridge lane. Provider breadth is split into
`docs/workstreams/addon-notification-provider-adapters/`.

## Rationale

The host/addon delivery contract is now proven. A real provider adapter needs a
separate decision about credentials, message templates, provider API calls,
provider-specific retry, rate limits, redaction, and operator configuration.
No first provider target has been selected yet, so implementing Telegram,
Discord, Home Assistant, email, or generic webhooks here would hard-code
product and operations choices prematurely.

## What Changed

- Opened `addon-notification-provider-adapters` as a draft follow-on workstream.
- Made ANP-010 the first follow-on task for provider selection and boundary
  freeze.
- Updated ANB docs so closeout can proceed without leaving provider breadth as
  unowned prose.
