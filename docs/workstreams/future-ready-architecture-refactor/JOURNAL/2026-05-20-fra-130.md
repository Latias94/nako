# FRA-130 — Deletion Sweep

Date: 2026-05-20

## Scope

Delete obsolete compatibility and stale documentation left behind by the
previous architecture slices. Avoid deleting ignored local artifacts or any
file that could be a user edit.

## Deletions

- Removed the `taru-api` root-level compatibility re-export shim:
  `admin::*`, `extension::*`, `metadata_diagnostics::*`, and
  `public_client::*`.
- Updated all touched callers to use explicit API boundary modules. This makes
  API ownership visible at import sites and prevents new server code from
  accidentally treating all DTOs as one flat namespace.
- Removed stale raw-job response examples from `docs/api/HTTP_API.md` and
  replaced them with the redacted `has_input`, `has_summary`, and `has_error`
  envelope introduced by FRA-110.

## Audited And Kept

- `admin::managed_artwork::*` is still re-exported inside the Admin API module.
  It is an internal aggregation point for the Admin API surface, not a root
  compatibility facade. Splitting it is a future Admin module-size decision,
  not a deletion-sweep blocker.
- `taru-search` still keeps explicit facet-label adapter helpers because the
  current HTTP query string shape and test fixtures still enter as strings.
  These helpers are fallible adapters into semantic Browse Facets, not hidden
  legacy search semantics.
