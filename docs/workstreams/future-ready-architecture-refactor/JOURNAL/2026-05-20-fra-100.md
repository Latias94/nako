# 2026-05-20 — FRA-100 Search Semantics

## Task

Deepen `taru-search` into a semantic search module with explicit projection
versioning, normalized fields, Browse Facets, Sort Keys, aliases, and provider
identifiers.

## Findings

Before this slice, `taru-search` was mostly a thin storage-facing trait:
`SearchDocument` held `title`, `body`, and raw `Vec<String>` facets, while the
SQLite adapter filtered facets by substring containment over `facets_text`.
That made search semantics table-shaped and imprecise: `genre:Science` could
match `genre:Science Fiction`, and aliases/provider IDs/sort keys had no
first-class shape.

The clean target is that callers build Taru search semantics once, then each
storage engine indexes or persists that semantic projection in its own way.
SQLite can keep a simple table-backed index for now, but it should adapt the
semantic projection rather than define the public model.

## Changes

- Added semantic search projection fields and helper methods in `taru-core`:
  projection version, Browse Facets, Sort Keys, aliases, provider identifiers,
  label parsing, and searchable text projection.
- Made keyed facet forms explicit for provider identifiers and custom credit
  roles. Example: `external_id:tmdb:603` is parsed as an External ID facet with
  provider key `tmdb` and value `603`, not as an ambiguous three-part string.
- Changed `taru-search` records so `SearchDocument` and `SearchQuery` carry
  semantic Browse Facets. Legacy raw facet-label construction is now explicit
  and fallible through `from_facet_labels`.
- Reworked catalog hydration and library indexing to build semantic search
  projections from item facts, labels, sources, credits, aliases, release year,
  sort titles, and provider IDs.
- Extended the SQLite-owned `search_documents` schema with projection version,
  aliases JSON, sort keys JSON, and provider identifiers JSON.
- Changed SQLite search persistence to write `projection.searchable_text()` and
  exact facet labels derived from Browse Facets.
- Changed SQLite search filtering to parse `facets_json` and require exact
  case-insensitive facet-label equality, removing the old substring filter over
  `facets_text`.
- Updated server, catalog, metadata, NFO, addon, and library tests/callers to
  use semantic search query/document construction.

## Tests Added

## Follow-up

FRA-110 should audit API and generated contracts. Search storage engine choices
are intentionally deferred: callers now depend on the semantic projection
contract, so a future SQLite FTS, Tantivy, PostgreSQL full-text, or hybrid
index can change behind the adapter boundary.
