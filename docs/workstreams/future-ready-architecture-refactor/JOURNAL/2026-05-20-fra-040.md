# FRA-040 — SQLite-Owned Adapter Split

Date: 2026-05-20
Status: Complete.

## Intent

Remove the `SqliteStore` god-adapter shape from Nako's public and root
`nako-db` boundaries without losing existing behavior. The split should improve
PostgreSQL portability by making SQLite identity, migrations, connection
runtime policy, row-codec helpers, and repository SQL clearly SQLite-owned
while preserving a small `nako-db` facade surface.

## Changes

- Added `crates/nako-db/src/sqlite.rs` as the SQLite-owned adapter module.
- Added `crates/nako-db/src/facade.rs` with `NakoDatabase` as the public
  database facade.
- Kept `SqliteRuntimeOptions` public for SQLite runtime tuning, but made
  `SqliteStore` crate-private so downstream crates cannot bind to the concrete
  SQLite adapter.
- Moved job persistence implementation to `crates/nako-db/src/sqlite/jobs.rs`.
- Moved SQLite-backed search index implementation to
  `crates/nako-db/src/sqlite/search.rs`.
- Moved SQLite library, library-item, metadata, and scan persistence
  implementations to `crates/nako-db/src/sqlite/`.
- Moved SQLite media, provider-mapping, and catalog persistence
  implementations to `crates/nako-db/src/sqlite/`.
- Rewired scan, metadata, and search transaction helper calls to use
  `crate::sqlite::{media,provider_mapping,catalog}` paths instead of root
  module paths.
- Moved SQLite ingestion, local-inference, staging, playback, and
  user-playback persistence implementations to `crates/nako-db/src/sqlite/`.
- Rewired scan workflow commits to use
  `crate::sqlite::{ingestion,local_inference}` transaction helpers instead of
  root module paths.
- Moved SQLite Addon, automation, event outbox, webhook, catalog-governance,
  source-duplicate, VFS cache, and artwork persistence implementations to
  `crates/nako-db/src/sqlite/`.
- After this slice, root `crates/nako-db/src` no longer contained repository
  implementation modules; it contained facade, codec, contract tests, the
  SQLite module declaration, crate root, and SQLite-specific tests.
- Moved the SQLite row-codec/helper module to
  `crates/nako-db/src/sqlite/codec.rs`; root `crates/nako-db/src` now contains
  only facade, contract tests, the SQLite module declaration, crate root, and
  SQLite-specific tests.
- Moved SQLite runtime connection policy to
  `crates/nako-db/src/sqlite/runtime.rs`.
- Moved SQLite migrations to `crates/nako-db/src/sqlite/migrations.rs` and
  adjusted migration include paths after the module move.
- Updated server app services, HTTP/app tests, and touched downstream crate
  tests to use `NakoDatabase`.
- Moved the FRA-030 job lease contract tests to construct `NakoDatabase`, so
  the contract now proves behavior at the facade boundary instead of the
  SQLite adapter boundary.
- Deleted the broad `sqlite::prelude` shim. SQLite modules now import
  `SqliteStore`, SQLite codec helpers, `nako_core`, `nako_search`, and `sqlx`
  types explicitly instead of inheriting a single large compatibility import.
- Removed the root `nako-db` internal prelude re-export. The public root now
  exposes only `NakoDatabase` and `SqliteRuntimeOptions`.
- Moved main `nako-db` behavior tests from direct `SqliteStore` construction
  to `NakoDatabase` construction. Tests that intentionally verify SQLite
  internals remain inside SQLite-owned modules.
- Confirmed `crates/nako-db/src` now contains only `contract_tests.rs`,
  `facade.rs`, `lib.rs`, `sqlite.rs`, and `tests.rs`.

## Concerns

- `NakoDatabase` is currently a simple single-backend facade. It intentionally
  avoids a fake PostgreSQL abstraction until FRA-050/FRA-060 identifies the
  real migration, SQL dialect, transaction, and contract-test proof shape.
- Some SQLite-owned submodule tests still construct `SqliteStore` directly.
  That is intentional: they test SQLite migration/runtime/rollback details
  rather than the backend-neutral facade contract.
- Full workspace nextest was not run for this slice. Full `nako-db` nextest,
  full `nako-server` nextest, workspace test compilation, formatting, and diff
  checks cover the changed persistence facade and server construction behavior
  while keeping the closeout gate proportional.

## Next Slice

Continue with FRA-050. Inventory the SQLite-specific migration, schema,
row-codec, SQL dialect, and fixture assumptions now isolated under `sqlite/`;
then choose the smallest PostgreSQL readiness proof for FRA-060.
