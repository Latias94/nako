# BPAT-040 Journal

Date: 2026-05-26

## Goal

Replace the Media Web safe watch placeholder with a real browser player backed
by short-lived browser playback tickets.

## Changes

- Added `MediaWebDataSource.createBrowserPlaybackTicket` and wired the live
  data source to the generated Public Client SDK ticket route.
- Resolved ticket URL descriptors against the configured server base URL before
  handing them to the browser player.
- Added fixture ticket generation for direct, remux, and HLS modes.
- Replaced the watch placeholder with an HTML5 `<video>` player that uses the
  browser-safe ticket URL envelope.
- Added focused tests for live SDK ticket issuance, fixture ticketing, selected
  source playback, and visible-text redaction.

## Verification

- `cd apps/admin-web && npm run test -- mediaDataSource.test.ts mediaSurface.test.tsx`
- `cd apps/admin-web && npm run check`
- `cd apps/admin-web && npm run build`
- `rg -n "admin/v1|AdminApi|adminApi|source_locator|local path|ffmpeg|Bearer |Authorization" apps/admin-web/src/surfaces/media`
- Playwright smoke on `http://127.0.0.1:4173/media`:
  - desktop watch page rendered a `<video controls>` player;
  - 390x844 mobile viewport rendered a nonblank player with stable dimensions;
  - visible page text did not contain the fixture ticket, raw `/sources/` path,
    `Bearer`, or `Authorization`.

## Notes

- The raw ticket appears only in the media element URL attribute, which is the
  accepted browser transport boundary for this lane.
- The fixture smoke logs an expected media-load error because
  `https://fixture.nako.test/...` is not backed by a real media service.
- Boundary grep only matched test assertions that verify SDK Authorization
  headers for JSON Public Client calls.
