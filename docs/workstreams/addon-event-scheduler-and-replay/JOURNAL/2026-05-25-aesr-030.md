# AESR-030 — In-Flight Guard And Automatic Retry

Status: DONE
Date: 2026-05-25

## What Changed

- Added a durable Addon Event delivery claim API to the repository boundary.
- Added SQLite and PostgreSQL lease migrations with `lease_expires_at` on
  `addon_event_delivery_attempts`.
- Claiming work now creates a `running` attempt atomically, blocks duplicate
  active claims for the same addon/event/subscription tuple, skips succeeded
  tuples, respects max attempts, and only retries failed attempts when
  `next_retry_at` is due.
- Addon Event delivery now claims before calling the sidecar and before taking
  the sidecar execution semaphore, so concurrent schedulers can observe the
  in-flight durable fact.
- Scheduler diagnostics now expose lease expiry as redaction-safe state and
  treat active leases as in-flight while allowing expired leases to become
  retry-due.
- Added focused DB and server tests for claim behavior, concurrent delivery
  dedupe, waiting retry skip, and retry-after-due delivery.
