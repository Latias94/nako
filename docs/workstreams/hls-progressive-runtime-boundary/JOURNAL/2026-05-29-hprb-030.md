# HPRB-030 Journal — Progressive HLS Server Readiness

Date: 2026-05-29
Status: DONE

## Summary

Implemented playlist-facing HLS readiness for app and HTTP entry points. The
server HLS service now uses `HlsOutputPublicationPolicy::ServeWhileRunning`,
starts the long-running HLS transcode under the runtime supervisor, and returns
the playlist after the playlist file exists while the transcode session remains
`Running`.

## Changes

- Split HLS source planning from execution so playlist readiness can observe the
  transcode session without blocking on full FFmpeg completion.
- Added background HLS startup for playlist requests, with reuse of active or
  finished sessions for the same request key.
- Prepared FFmpeg input before background spawn to avoid hiding pre-session
  staging/input failures behind the readiness timeout.
- Returned playback-session-scoped HLS playlists after linking the playback
  session to the running transcode session.
- Added app and HTTP tests for running-session playlist readiness, generated
  segment serving, missing segment not-ready conflicts, and cancellation.

## Review Notes

Review found one important issue before closeout: if input staging failed after
spawning the background HLS task but before a transcode session was persisted,
the playlist request would wait for the readiness timeout. The implementation
now prepares FFmpeg input in the foreground before spawning the background task.
