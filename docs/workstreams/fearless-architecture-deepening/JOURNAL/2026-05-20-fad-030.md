# 2026-05-20 — FAD-030 Addon Metadata Commit Atomicity

## Scope

Deepened Addon Canonical Metadata persistence so the server no longer orders
metadata mutation, catalog/search projection, and apply-outcome recording across
separate repository calls.

## Changes

- Added `AddonMetadataWritePersistenceCommit`,
  `AddonMetadataWriteCatalogCommit`, and summary types in `nako-core`.
- Added `MetadataRepository::commit_addon_metadata_write`.
- Implemented the seam in SQLite and PostgreSQL with one transaction covering:
  - `MediaItem` upsert;
  - optional Catalog Item Graph replacement;
  - Search Projection upsert;
  - Addon Side Effect `Applied` outcome.
- Refactored SQLite/PostgreSQL Addon Side Effect outcome persistence into
  transaction helpers so the metadata commit seam can reuse the exact outcome
  semantics.
- Added catalog planning helpers for search-only and label-focused projection
  commits.
- Updated server Addon metadata write apply to build the commit and return the
  recorded outcome.
- Added a backend-neutral contract proving search-only writes, graph writes,
  apply outcome recording, and rollback.
