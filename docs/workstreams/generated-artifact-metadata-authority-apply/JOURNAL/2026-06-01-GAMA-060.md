# GAMA-060 - Web Admin Metadata Authority Apply

Date: 2026-06-01
Status: DONE

## Scope

Implemented the Web Admin apply-plan and confirm-apply workflow after Generated
Artifact review acceptance. Backend route and persistence behavior stayed under
the existing GAMA-020 through GAMA-050 authority.

## Changes

- Added Admin data-source support for
  `POST /admin/v1/automation/generated-artifacts/{artifact_id}/metadata-apply-plan`
  and
  `POST /admin/v1/automation/generated-artifacts/{artifact_id}/metadata-apply`.
- Added a separate Metadata Authority apply route at
  `/admin/automation/generated-artifacts/metadata-apply?artifact_id=...`.
- Wired accepted review results to the apply page without making review apply
  metadata.
- Rendered redacted plan facts, field actions, reasons, counters, target ids,
  payload fingerprints, and outcome ids without raw Generated Artifact content.
- Required operator preparation before final apply and generated a stable UI
  idempotency key per apply attempt.
- Disabled final apply for fixture/fallback plans.
- Compacted low-frequency mock-only Admin settings pages to placeholders so the
  real GAMA workflow stayed inside the existing Admin route budget.
