# MAPG-010 — Scope And Split Baseline

Date: 2026-05-20

## Summary

MAPG-010 activated the Managed Artwork PostgreSQL parity lane and confirmed the
PGR-090 split. PostgreSQL currently has explicit unsupported stubs for
`ArtworkCandidateRepository` and `ManagedArtworkRepository`, while SQLite owns
the full behavior across candidate intake, ingest jobs, artifacts, Selected
Artwork, gallery snapshots, lifecycle cleanup, drift/remediation diagnostics,
and selected-image variant serving.

## Inventory

- SQLite migrations: `0025_addon_artwork_candidates.sql`,
  `0026_managed_artwork_ingest.sql`,
  `0027_selected_artwork_publication.sql`, and
  `0028_managed_artwork_artifact_cleanup.sql`.
- SQLite modules:
  `crates/taru-db/src/sqlite/artwork/{candidate,ingest,artifact,selected,gallery,lifecycle}.rs`.
- PostgreSQL target: add native PostgreSQL schema/migration coverage and replace
  unsupported stubs in `crates/taru-db/src/postgres.rs`.
- Server boundary: `ManagedArtworkAppService` uses repository traits and
  local artifact-store bytes; no provider-specific or file-path data needs to
  cross public/Admin DTO boundaries.

## First Slice

MAPG-020 will add backend-neutral contracts and PostgreSQL implementation for
Addon Artwork Candidate intake plus Managed Artwork candidate acceptance /
ingest queue creation.
