# SVRS-020 Journal — Source Identity Evidence Policy

Date: 2026-05-29

## Summary

Implemented the first layered **Source Fingerprint** evidence policy for scan
commits.

## Changes

- Added `SourceFingerprintEvidenceKind`, `SourceFingerprintPolicyInput`, and
  `SourceFingerprintEvidence` in `nako-core`.
- Changed `VfsLibraryScanner` to derive fingerprints from layered scan metadata
  instead of persisting raw backend fingerprint strings.
- Kept normal scan hash-free: size + ETag and size + modified time evidence are
  hashed from metadata only; no file range/open operation is required.
- Preserved the safety boundary that duplicate fingerprints do not automatically
  merge distinct **Media Sources**.

## Validation

- `cargo nextest run -p nako-core source_fingerprint --no-fail-fast`
- `cargo nextest run -p nako-library source_identity scan --no-fail-fast`
- `cargo fmt --all -- --check`
- `git diff --check`
- `cargo check -p nako-core -p nako-db -p nako-vfs -p nako-library -p nako-server --tests`

SQLite/PostgreSQL repository contract tests were not required because this
slice did not change schema, migrations, or repository contracts.

## Follow-On

SVRS-030 should use the policy output for move/rename reconciliation. Only
strong evidence should preserve source identity automatically; weaker evidence
belongs in reviewable duplicate or reconciliation state.
