# SVRS-030 Journal — Move/Rename Reconciliation

Date: 2026-05-29

## Summary

Implemented the first move/rename reconciliation slice for **Media Source**
identity. Strong content-hash evidence can now preserve an existing source and
item state across a locator change. Weak evidence and duplicate files remain
reviewable through **Source Duplicate Relationship** records instead of
automatic merges.

## Implementation Notes

- `DiscoveredMediaSource` now carries fingerprint evidence kind and confidence
  from the `SourceFingerprintEvidence` policy.
- `LibraryIndexService` passes all locators observed in the current scan into
  source observation commits, so a same-fingerprint file that is still present
  in the current scan is treated as a duplicate candidate rather than a move.
- Source observation planning reuses an existing **Media Source** only when
  strong evidence finds exactly one prior same-fingerprint candidate and that
  old locator is not present in the current scan.
- Duplicate/reconciliation candidates are persisted as suggested
  **Source Duplicate Relationship** records with confidence and redacted
  evidence value.
- SQLite and PostgreSQL scan source commits now upsert duplicate relationships
  inside the same transaction as source, state, inference, search, and failure
  resolution records.
