# FFR-050A VFS Local Path Authority Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-vfs/src/local.rs`
- `crates/nako-vfs/src/local/path_authority.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `local/path_authority.rs` and moved local root canonicalization,
  scheme validation, relative path parsing, read/write/cleanup path
  resolution, local URI creation, backup URI creation, and security-violation
  classification out of `local.rs`.
- Kept `LocalFsBackend` behavior unchanged: read, write, atomic replace,
  backup pruning, link planning/apply, cleanup, restore, and staging still use
  the same storage reports and status mapping.
- Added focused path-authority tests for parent-directory traversal rejection
  and local URI separator normalization.
- Removed the old `relative_path`, `local_path_error_is_security_violation`,
  and `uri_for_local_path` helpers from `local.rs`.

## Validation

- `cargo nextest run -p nako-vfs local --no-fail-fast` passed with 36 tests
  run and 11 skipped.
- `cargo nextest run -p nako-vfs --no-fail-fast` passed with 47 tests run.
- `cargo fmt --package nako-vfs` completed.
- `cargo fmt --package nako-vfs -- --check` passed.
- `git diff --check` passed with Git CRLF normalization warnings only.

## Judgment

- This is the right first FFR-050 cut because local URI/path safety was reused
  by every local backend operation. Moving it gives future file-write policy,
  link planning, cleanup, and restore changes a single authority for root
  escape checks.
- `local.rs` is still broad. The next best cut is likely a local write
  transaction module for atomic replace, backup creation, restore, sync, and
  backup pruning.
