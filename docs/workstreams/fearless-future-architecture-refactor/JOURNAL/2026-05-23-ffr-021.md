# FFR-021 Managed Import Runtime Split

## Summary

- Selected `managed_import` as the next `nako-server::app` hotspot because the
  file mixed service orchestration, diagnostics output, URI redaction, promotion
  outcome JSON, storage apply status mapping, and catalog commit failure
  reporting.
- Split artifact and promotion acceptance diagnostics into `diagnostics.rs`.
- Split accepted plan JSON, accepted warning JSON, storage outcome JSON, cleanup
  completion, and storage apply safe error mapping into `outcomes.rs`.
- Kept the existing `managed_import.rs` exports stable through local re-exports.

## Validation

- `cargo check -p nako-server --tests`: passed.
- `cargo nextest run -p nako-server managed_import --no-fail-fast`: passed with
  19 tests run and 251 skipped.
- `cargo fmt --package nako-server`: completed.

## Notes

This was a behavior-preserving split. `ManagedImportAppService` still owns the
promotion workflow orchestration, storage backend calls, and catalog commit
sequence. Future work can split destination planning, storage apply command
construction, and catalog commit into deeper modules without first untangling
diagnostic or outcome JSON code.

Continue with FFR-030 by splitting the `nako-db` PostgreSQL-ready persistence
boundary.
