# FFR-040E API Admin Operations Surface Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-api/src/admin.rs`
- `crates/nako-api/src/admin/operations.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `admin/operations.rs` and moved job, job cancellation, outbox event,
  ingestion failure, and ignore-ingestion-failure DTOs out of `admin.rs`.
- The operations module now owns conversion from core job, cancellation,
  outbox, and ingestion failure records into admin-safe operational summaries.
- Kept raw job inputs, job summaries, raw errors, outbox payload JSON,
  idempotency keys, and last errors behind boolean summary fields.
- Kept the public `nako_api::admin::*` import shape stable through
  `pub use operations::*`.
- Moved operational redaction tests into the new module so job/outbox payload
  safety and ingestion failure flattening stay local to the operations API
  surface.

## Judgment

- Operations was a higher-leverage split than config diagnostics because it
  owns active admin workflows and repeated redaction rules across jobs, outbox
  events, and ingestion failures.
- After FFR-040E, `admin.rs` primarily owns catalog governance, server config
  diagnostics, and overview summary DTOs. Those remaining surfaces are smaller
  and mostly passive. Run a review gate before deciding whether to split
  config/overview or move to FFR-050.
