# FFR-030G PostgreSQL Metadata/Catalog Backend Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-db/src/postgres.rs`
- `crates/nako-db/src/postgres/metadata_catalog.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `postgres/metadata_catalog.rs`.
- Moved PostgreSQL `ProviderMappingRepository`, `MetadataRepository`, and
  `CatalogRepository` implementations out of the broad `postgres.rs` backend.
- Moved provider subject, provider mapping, metadata field lock, provider raw
  response, metadata provider attempt, metadata commit, catalog graph
  replacement, catalog entity, and image asset row mapping into the new module.
- Moved the related provider/source/subject-kind/credit-role/image-owner
  codecs with the SQL family that owns their storage representation.
- Kept shared media item, library item state, search projection, and
  external-id lookup helpers in `postgres.rs` until FFR-030H decides whether
  they are stable infrastructure or another meaningful backend family.

## Notes

- `postgres.rs` is now around 3,000 lines. The largest persistence risk has
  been reduced substantially, but the file still owns several smaller backend
  families.
- FFR-030H should decide whether another meaningful split remains inside
  `postgres.rs`. The likely candidates are source duplicate plus catalog
  governance, playback plus transcode runtime state, or library/media/scan
  primitives.
