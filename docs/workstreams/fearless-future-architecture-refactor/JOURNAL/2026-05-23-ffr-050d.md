# FFR-050D VFS Local Lifecycle Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-vfs/src/local.rs`
- `crates/nako-vfs/src/local/lifecycle.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `local/lifecycle.rs` and moved local cleanup, restore, lifecycle
  request validation, lifecycle status mapping, and cleanup/restore report
  construction out of `local.rs`.
- Kept `LocalFsBackend` as the storage trait entrypoint, delegating `cleanup`
  and `restore` into the lifecycle module.
- Preserved the earlier local module boundaries: path authority owns safe
  path resolution, apply-plan owns copy/link readiness and apply, and
  write-transaction owns atomic write, backup, restore temp-file, and fsync
  mechanics.

## Judgment

- The VFS local backend now has explicit internal modules for the main behavior
  families: path authority, apply/link planning, cleanup/restore lifecycle,
  and write transactions. `local.rs` is closer to a storage backend facade plus
  shared stat/range/read/write/stage helpers.
- FFR-050 should now move to local inference and naming boundaries. That is
  the remaining risk for explainable parser evidence and future metadata/NFO
  authority work before FFR-060.
