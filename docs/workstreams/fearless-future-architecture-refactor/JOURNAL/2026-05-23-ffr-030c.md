## Changes

- Chose VFS cache and staging manifest persistence for FFR-030C because the
  SQL select fragments, row mapping, listing transaction, staging reservation
  budget, and lease state transitions are cohesive and have direct focused
  contract coverage.
- Added `postgres/vfs_staging.rs` and moved `VfsCacheRepository`,
  `StagingManifestRepository`, VFS/staging SQL fragments, transaction helpers,
  budget helpers, and row mappers into that module.
- Kept `postgres.rs` as the PostgreSQL backend composition point with
  `mod vfs_staging;`; no schema, trait, or public API shape changed.
