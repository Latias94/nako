# FFR-050E Naming And Local Inference Boundary Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-naming/Cargo.toml`
- `crates/nako-naming/src/lib.rs`
- `crates/nako-library/src/local_inference.rs`
- `Cargo.lock`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Removed the `nako-naming` dependency on `nako-core`.
- Added parser-local `ParsedMediaKind` and `NameEvidenceSource` output types
  in `nako-naming`, replacing direct use of Nako catalog `MediaKind` and
  `LocalInferenceEvidenceSource`.
- Moved parsed-name to Nako-domain mapping into
  `nako-library/src/local_inference.rs`, where the library local-inference
  boundary already constructs `MediaItem`, `SourceState`, `MediaSource`, and
  `LocalInferenceEvidence`.
- Added a custom-parser boundary test proving that library local inference maps
  parser output into Nako `MediaKind` and `LocalInferenceEvidenceSource`.

## Judgment

- `nako-naming` is now a future-facing parser crate that can support built-in,
  plugin, or AI-assisted parsers without importing catalog persistence/domain
  evidence types.
- `nako-library` remains the correct boundary for translating parser output
  into Nako catalog records and Local Inference Evidence because it already
  owns scan ingestion and source observation commits.
- FFR-050 is close to review. If one more cut is needed before closure, split
  `local_inference.rs` internally by planning/mapping, not by pushing Nako
  domain types back into the parser crate.
