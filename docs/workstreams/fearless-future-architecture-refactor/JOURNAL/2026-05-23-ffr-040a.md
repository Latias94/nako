# FFR-040A API Admin Playback And Network Surface Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-api/src/admin.rs`
- `crates/nako-api/src/admin/playback.rs`
- `crates/nako-api/src/admin/network.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `admin/playback.rs` and moved the admin playback DTO surface out of
  `admin.rs`.
- The playback module now owns playback session list DTOs, runtime
  diagnostics, support evidence, hardware readiness summaries, request-key
  fingerprinting, source-scheme redaction, and playback redaction tests.
- Added `admin/network.rs` and moved the admin network access diagnostics
  surface out of `admin.rs`.
- The network module now owns exposure mode, readiness checks, external
  endpoint, trusted proxy, origin policy, tunnel provider diagnostics, and
  network readiness/redaction tests.
- Kept the public `nako_api::admin::*` import shape stable with module-local
  `pub use` re-exports while moving implementation and tests behind focused
  admin surfaces.

## Judgment

- `FFR-040` should continue. Playback and network are now focused admin API
  surfaces, but `admin.rs` still owns multiple unrelated API faces including
  config diagnostics, storage/staging diagnostics, automation review, intake,
  governance, jobs, outbox, overview, ingestion failures, and storage backend
  diagnostics.
- The next cut should choose another high-locality API surface rather than
  splitting by line count. Good candidates are config diagnostics or
  storage/staging diagnostics because both have explicit redaction and contract
  tests.
