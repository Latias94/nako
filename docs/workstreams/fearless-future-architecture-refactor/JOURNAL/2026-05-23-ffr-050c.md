# FFR-050C VFS Local Apply/Link Planning Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-vfs/src/local.rs`
- `crates/nako-vfs/src/local/apply_plan.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `local/apply_plan.rs` and moved local link readiness planning,
  copy apply, hardlink/symlink apply, apply status mapping, and create-new
  copy/symlink file actions out of `local.rs`.
- Kept `LocalFsBackend` as the storage trait entrypoint, delegating
  `plan_link` and `apply` into the apply-plan module.
- Preserved the existing module responsibilities from earlier cuts:
  `path_authority.rs` owns safe path resolution and scheme checks, while
  `write_transaction.rs` owns atomic write, backup, restore temp-file, and
  fsync mechanics.

## Judgment

- This split separates local "can this file operation be applied?" policy from
  raw path authority and write-transaction mechanics. That gives future
  managed import, NFO sidecar, and library file-write policy a clearer VFS
  boundary to call into or wrap.
- `local.rs` is still broad around cleanup/restore report construction and
  general backend tests. The next FFR-050 cut should either split those
  cleanup/restore report boundaries or move into local inference/naming if
  parser explainability has become the larger risk.
