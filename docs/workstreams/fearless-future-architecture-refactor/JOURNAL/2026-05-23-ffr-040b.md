# FFR-040B API Admin Storage Surface Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-api/src/admin.rs`
- `crates/nako-api/src/admin/storage.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `admin/storage.rs` and moved storage-facing admin DTOs out of
  `admin.rs`.
- The storage module now owns staging diagnostics, staging record conversion,
  VFS cache summaries, storage backend diagnostics, backend runtime state
  scope, and storage redaction tests.
- Kept `nako_api::admin::*` call sites stable through `pub use storage::*`.
- Added a storage backend diagnostics test to keep runtime state summarized
  and to guard against leaking raw credential-bearing storage references.

## Judgment

- `FFR-040` should continue. The admin API file is now smaller and has three
  focused submodules (`playback`, `network`, `storage`), but it still owns
  multiple unrelated surfaces.
- The next best cut is likely configuration diagnostics or automation/intake
  DTOs. Config diagnostics are broad but mostly passive DTOs; automation and
  intake have richer conversion/redaction behavior and may provide better
  locality.
