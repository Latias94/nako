# FFR-040D API Admin Intake Surface Split

Date: 2026-05-23
Status: DONE

## Scope

- `crates/nako-api/src/admin.rs`
- `crates/nako-api/src/admin/intake.rs`
- `docs/workstreams/fearless-future-architecture-refactor/*`

## Changes

- Added `admin/intake.rs` and moved acquisition intake plus watch-folder
  discovery DTOs out of `admin.rs`.
- The intake module now owns source reference redaction fields, source key
  fingerprints, admission state diagnostics, and discovery failure summaries.
- Kept the public `nako_api::admin::*` import shape stable through
  `pub use intake::*`.
- Moved the intake redaction tests into the new module so source URI, display
  name, intended locator, diagnostics JSON, root URI, and local-path safety
  stay local to the intake API surface.

## Judgment

- Intake was a better FFR-040 cut than config diagnostics because it owns
  admission-specific redaction and watch-folder failure summaries rather than
  passive configuration mirrors.
- `admin.rs` still contained a cohesive operational admin surface after this
  split: jobs, cancellation requests, outbox events, and ingestion failures.
  That surface should be split before moving to FFR-050.
