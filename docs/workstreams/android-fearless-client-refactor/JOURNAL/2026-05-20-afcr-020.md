# AFCR-020 Journal — Token-Safe Playback Launch

Date: 2026-05-20

## Summary

Completed the P0 playback token-safety boundary. Playback route and launch
state no longer store raw authenticated `TaruHttpRequest` values. They now use
token-free `PlaybackRequestDescriptor` values and construct authenticated
requests only at explicit runtime seams.

## Changes

- Added `PlaybackRequestDescriptor` with:
  - header validation that rejects `Authorization`;
  - header value validation that rejects bearer-token shaped values;
  - computed safe request previews;
  - explicit `authenticatedRequest(accessToken)` final-request construction.
- Changed `PlaybackRequestTarget` and `PlaybackLaunchRequest` to store
  descriptors instead of raw `TaruHttpRequest`.
- Updated `TaruPlaybackClient` target builders so direct/remux/HLS/segment
  targets are token-free until preparation or player runtime.
- Kept session preflight authenticated only at the executor boundary, using the
  shared Public Client API redaction path from AFCR-010.
- Updated Media3 player construction so Authorization is injected from the
  active token only in the non-saveable runtime controller.
- Updated browse and player tests to use token-safe descriptors and added
  token-safety regressions for descriptor validation, launch diagnostics, direct
  target token requirements, Player route save payloads, and player error
  diagnostics.
