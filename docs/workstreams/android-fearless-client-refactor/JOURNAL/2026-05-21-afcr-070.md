# AFCR-070 Journal — Architecture Reassessment And Follow-On Split

Date: 2026-05-21

## Summary

Completed the AFCR-070 planner/reviewer pass after the Public Client API
adapter, token-safe playback launch descriptors, BrowseSession deepening,
network policy hardening, paging vertical, and product UI hardening had landed.

Decisions:

- Keep Kotlin package seams inside `:app` as the closeout shape for this lane.
- Do not generate a Kotlin SDK inside this refactor. Split it after the
  OpenAPI v1 artifact from ADR-0025 becomes the contract authority.
- Do not introduce shared Rust/UniFFI inside this refactor. Split it after a
  target-state document defines the narrow portable client-core interface and
  validation matrix.
- Do not split Gradle modules now. The current package seams provide locality
  and leverage; a module split needs a second adapter, generated SDK, or
  measurable build/dependency pressure.
- Defer artwork request descriptors until image caching, offline, or
  shared-core artwork routing begins.
- Defer broader Home/Library Detail paging to a product-scalability follow-on.
- Keep downloads/offline, external player handoff, and Android TV as product
  lanes with their own UX, permissions, and validation criteria.

## Architecture Notes

The deletion test supports the current modules:

- Deleting `PublicClientApiExecutor` would spread API-version checks, public
  error-envelope parsing, JSON decode failure mapping, transport failure
  mapping, request previewing, bearer redaction, and URL helper policy back
  into route clients.
- Deleting the extracted browse modules would re-concentrate navigation,
  route-family loading, stale response handling, search, detail/source
  selection, and playback start rules into one broad `BrowseSession`.
- Deleting `PlaybackRequestDescriptor` would reintroduce raw request/header
  knowledge into saveable route state and diagnostics.

These modules are deep enough for the foundation lane and provide the right
test surfaces for final verification.
