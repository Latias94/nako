# ACF-060 Playback Session And Resume Boundary

Status: COMPLETE
Date: 2026-05-18

## Scope

Audited the current Public Client API playback state boundary and implemented
the Android-side foundation that is safe to claim without server-authoritative
resume APIs.

## Changed

- Added Android DTO mirrors for Public Client API playback session responses.
- Added Android playback client methods for:
  - `GET /playback/sessions/{session_id}`;
  - `POST /playback/sessions/{session_id}/cancel`.
- Added playback launch metadata for active server profile, Media Item, Media
  Source, playback mode, optional session id, and device-local resume position.
- Added a device-local transient playback position store keyed by server
  profile id, Media Item id, and Media Source id.
- Wired Media3 launch to seek to local transient position when present.
- Wired Media3 route disposal to save or clear local transient position and to
  request cancellation only when the launch request already carries an explicit
  session id.

## API Boundary

- Existing public API coverage:
  - playback session inspection;
  - playback session cancellation.
- Missing public API coverage:
  - progress reporting;
  - resume lookup;
  - authoritative **User Playback State**.
- Current remux/HLS stream responses do not expose a session id to Android.
  HLS playlists contain session ids in segment URLs after generation, but the
  Android client should not parse playlists to invent lifecycle handles.

## Follow-Ups

- Add a Public Client API workstream for authoritative **User Playback State**
  before cross-device resume or Continue Watching is implemented.
- Decide whether stream responses should expose a public session id header or
  structured launch envelope for reliable native-client cancellation on exit.
- Choose durable Android persistence for device-local transient position if it
  should survive app process death.
