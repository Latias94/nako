# ACF-030D Search, Facet, And Walkthrough Hardening

Status: IMPLEMENTED_PENDING_MANUAL_WALKTHROUGH
Date: 2026-05-18

## Scope

Hardened the remaining non-playback browse routes after the Compose UI baseline
rewrite. The change wires only explicit Public Client API routes and records
unsupported browse targets as API gaps rather than adding Android-only pseudo
filtering.

## Changed

- Added Android DTO mirrors for search hits and related-item facet responses.
- Added direct Kotlin browse client support for:
  - `GET /search?q=&facet=&limit=&offset=`;
  - `GET /genres/{genre_id}/items`;
  - `GET /tags/{tag_id}/items`;
  - `GET /people/{person_id}/items`.
- Added unit tests for search query/facet/pagination encoding, search hit
  decoding, genre item result decoding, tag/person route construction, active
  profile use, and safe request redaction.
- Replaced the Search placeholder with a submitted-query screen backed by the
  active server profile.
- Replaced the Browse Facet placeholder with a result route for API-backed
  Genre, Tag, and Person targets.
- Converted facet navigation from string labels to `BrowseFacetTarget`, so
  display labels and stable ids are not conflated.
- Detail metadata chips now open Genre/Tag result routes only when the detail
  response includes stable relation ids.
- Detail person rows use `credits.person_id` when present and do not invent
  names that are missing from the response.

## API Gaps

- Library-scoped item browsing and library facets.
- Studio related-item route.
- Collection related-item route.
- Year related-item route.
- Media Item kind related-item route.
- Rich credit/person display data in item detail responses.
