# CRA-020 Route/API Repair Readiness

Date: 2026-05-25

## Claim

Catalog Repair Actions has an accepted first repair action and a concrete
backend/API handoff. Admin Web repair UI remains blocked until backend routes
and generated contract coverage exist.

## Audit Notes

- Existing read surface:
  - `GET /admin/v1/catalog/governance/items`
  - `NAKO_ADMIN_ROUTES.catalogGovernanceItems`
  - `AdminCatalogGovernanceItemListResponse`
  - Admin Web `/catalog/governance`
- Existing DTO redaction:
  - `AdminCatalogGovernanceItem::from_record` omits raw
    `LocalInferenceEvidence.evidence_value`.
  - The list route already avoids Source Locators, local paths, provider raw
    bodies, NFO paths/XML, tokens, and secrets.
- Existing Provider Mapping domain support:
  - `ProviderMappingStatus` has `candidate`, `accepted`, and `rejected`.
  - `ProviderMappingRepository` can list mappings for one Media Item and upsert
    mappings.
  - Provider Subject lookup can provide safe display facts for a mapping.
- Current gaps:
  - no item-scoped catalog repair detail route;
  - no Provider Mapping review-plan route;
  - no confirmed Provider Mapping mutation route;
  - no generated Admin Web route constants or DTOs for repair routes;
  - no dedicated mapping-ID lookup/status-update method, so CRA-030 must either
    add one or enforce item/mapping matching through an item-scoped list.

## Decision

The first repair action is Provider Mapping `accept` or `reject` scoped to one
Media Item ID and one Provider Mapping ID.

This action may update Provider Mapping status only. It must not update
Canonical Metadata, Provider Subjects, Local Inference Evidence, Source
Duplicate Relationships, hierarchy, NFO sidecars, Library Files, artwork,
playback state, or Public Client API state.

Unknown classification, Local Inference apply, duplicate-source repair,
hierarchy repair, rematch/provider search, Provider Subject editing, NFO
actions, and arbitrary metadata editing remain split.

## Handoff

Continue with CRA-030. Add redaction-safe detail/review-plan Admin API DTOs,
route constants, generated TypeScript contract coverage, and tests for unsafe
evidence exclusion before any UI control is added.
