# CRA-040 Confirmed Provider Mapping Mutation

Date: 2026-05-25

## Summary

Implemented the first real Catalog Governance repair mutation: confirming a
Provider Mapping `accept` or `reject` decision for one Media Item and one
Provider Mapping.

## Changes

- Added the confirmed Admin API mutation route:
  - `POST /admin/v1/catalog/governance/items/{item_id}/provider-mappings/{mapping_id}/review`
- Added idempotent response semantics:
  - first status change reports `changed: true`;
  - replay against the target status reports `changed: false` and
    `idempotent_replay: true`.
- Regenerated the Admin Web contract with mutation route constants and response
  DTOs.
- Added `AdminApiClient.reviewCatalogGovernanceProviderMapping`.
- Added `AdminDataSource` wrappers for:
  - item detail;
  - Provider Mapping review-plan;
  - confirmed Provider Mapping review mutation.
- Added safe summary projections that keep result rendering scoped to item,
  mapping, decision, status, readiness, and boundary facts.
- Kept deterministic fallback for read/detail/review-plan paths only.
- Ensured mutation failure does not report fake success.
- Updated `docs/api/HTTP_API.md` with confirmed mutation semantics and
  non-mutated boundaries.

## Verification
