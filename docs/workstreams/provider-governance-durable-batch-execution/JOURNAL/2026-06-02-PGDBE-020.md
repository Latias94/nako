# PGDBE-020 Journal

Date: 2026-06-02
Task: PGDBE-020
Status: DONE

## Summary

Added the durable Candidate Review batch persistence foundation:

- `nako-core` now has Candidate Review batch IDs, statuses, plan summaries,
  execution summaries, item records, item outcome commits, and an explicit
  `MetadataCandidateReviewBatchApply` job kind/resource class.
- `MetadataCandidateReviewRepository` now owns the batch persistence contract:
  idempotent commit, idempotency-key lookup, batch status update, batch get, and
  per-item outcome commit.
- `nako-db` now has SQLite and PostgreSQL baseline tables plus repository
  implementations for durable Candidate Review batches.
- Repository contract coverage proves idempotent replay, transactional rollback
  on conflicting item idempotency keys, job persistence/rollback, item order
  preservation, status compare-and-set failure, and per-item outcome summary
  updates.

## Boundary Decisions

- The batch state is Candidate Review specific; it does not reuse Generated
  Artifact bulk apply tables.
- `PGDBE-020` does not add Admin routes, Web UI, Public Client API exposure, or
  job execution behavior.
- Item outcome commits only mutate batch item state. Provider Subject, Provider
  Mapping, and Canonical Metadata writes remain outside this task.
- PostgreSQL support was implemented alongside SQLite even though the local
  contract test is ignored without `NAKO_TEST_POSTGRES_URL`.
