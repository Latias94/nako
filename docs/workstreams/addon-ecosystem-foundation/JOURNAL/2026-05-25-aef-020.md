# 2026-05-25 — AEF-020 Addon Task Request Fingerprints

Status: DONE

Implemented deterministic Addon Task request fingerprints at the domain model,
SQLite/PostgreSQL persistence, and server runtime boundaries. The repository
now treats `(addon_id, idempotency_key)` as a replay key only when the stored
fingerprint matches the incoming request fingerprint; mismatches return
`NakoError::Conflict` instead of silently returning the previous run.

Key decisions:

- Fingerprints include manifest id, manifest version, manifest fingerprint,
  task declaration id, declaration path, and the canonical task input JSON.
- The input JSON already carries dispatch mode, library/source targeting,
  payload, retry lineage, attempt, and normalized idempotency key, so the
  fingerprint follows the host-owned runtime request facts.
- Because Nako has no deployed users, the schema was updated directly rather
  than adding compatibility migrations for historical rows.
