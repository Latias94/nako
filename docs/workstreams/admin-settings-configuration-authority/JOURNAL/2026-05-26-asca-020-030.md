# ASCA-020/030 - Metadata Raw Cache Settings Authority

Status: DONE_WITH_CONCERNS
Date: 2026-05-26

## Decision

The first Admin-mutated global settings field group is metadata raw cache
retention:

- `metadata.raw_cache_retention_ms`
- `metadata.maintenance.raw_cache_cleanup_on_startup`

The field group is persisted as an Admin desired-state override. Startup loads
TOML first and then applies the Admin override before services and startup
workflows are built.

PUT does not hot-apply the current process. The route reports
`effect = requires_restart` until restart when the persisted override differs
from active config. After restart, the route reports `effect = active`.

## Implementation

- Added `AdminMetadataRawCacheSettings*` domain records and
  `AdminSettingsRepository`.
- Added SQLite and PostgreSQL migrations/repository adapters.
- Moved app composition migration before service construction so startup merge
  can read Admin settings.
- Added `GET|PUT /admin/v1/settings/metadata/raw-cache`.
- Added Admin API DTOs and regenerated the Admin Web TypeScript contract.
- Added HTTP API documentation and focused server/DB/API tests.

## Concern

Admin Web settings UI is unblocked only for this metadata raw cache field
group. Broader global settings still need their own accepted backend authority
and must not be shown as editable save controls.
