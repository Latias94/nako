# NSPA-030 Journal — Server Acceptance And Replay

Date: 2026-05-21
Owner: codex
Status: DONE

## Scope

Implemented the server app-service boundary for accepting an NFO authority
preview as a durable sidecar apply attempt. This task intentionally does not
write NFO sidecar files and does not mutate canonical metadata.

## Red Gate

```powershell
cargo nextest run -p taru-server nfo_sidecar_apply --no-fail-fast
```

Expected failure before implementation: the new behavior tests could not
compile because `AcceptNfoSidecarApplyRequest` and `accept_sidecar_apply` did
not exist.

## Implementation

- Added `AcceptNfoSidecarApplyRequest` and
  `NfoSidecarApplyAcceptanceDiagnostic`.
- Added `NfoAppService::accept_sidecar_apply`.
- Added idempotency-key replay validation.
- Added preview revalidation against the current NFO authority preview.
- Added stale/mismatched preview rejection.
- Stored accepted preview snapshots in a server-owned stable JSON shape.
- Kept accepted warnings as safe warning-code tokens rather than raw operator
  JSON.
- Preserved the no-mutation boundary: acceptance records audit intent only.

## Validation

```powershell
cargo nextest run -p taru-server nfo_sidecar_apply --no-fail-fast
cargo nextest run -p taru-server nfo_authority_preview --no-fail-fast
cargo nextest run -p taru-server nfo --no-fail-fast
cargo nextest run -p taru-db nfo_sidecar_apply --no-fail-fast
cargo nextest run -p taru-nfo --no-fail-fast
cargo nextest run -p taru-vfs --no-fail-fast
cargo fmt --all -- --check
python -m json.tool docs/workstreams/nfo-sidecar-promotion-apply/WORKSTREAM.json
git diff --check
```

All commands passed except `cargo nextest run -p taru-vfs nfo --no-fail-fast`,
which returned nextest's no-tests error because no `taru-vfs` tests match the
`nfo` filter. Full `taru-vfs` passed.

`git diff --check` emitted only repository CRLF conversion warnings.
