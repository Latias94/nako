## Summary

Added bounded backend batch confirmation for Metadata Candidate Reviews. The
Admin API now accepts selected review rows, preserves per-row stale guards and
idempotency-key fingerprinting, applies only eligible root Provider Mapping
rows through the existing single-review application authority, and returns
redaction-safe partial results.

## Implementation

- Added `POST /admin/v1/metadata/candidate-reviews/batch-apply`.
- Added batch apply request, summary, result status, result row, and error DTOs.
- Deepened `MetadataCandidateReviewApplicationService` with a stale-aware
  `plan` method reused by `apply`.
- Kept batch execution synchronous and bounded at 50 rows.
- Synchronized generated Admin TypeScript contracts in `apps/admin-web` and
  `web`.

## Notes

The batch route does not introduce a durable job because the current mutation
is bounded, synchronous, and root-only. Future retry/cancel/progress behavior
should split a durable control-plane job rather than hiding background work in
the Web confirmation flow.
