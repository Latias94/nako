# AOTDC-030 Direct Dispatch Injection

Date: 2026-05-24

Implemented direct dispatch credential injection for addon sidecars.

What changed:

- `crates/nako-server/src/app/addons/task_runtime.rs` now resolves the host-owned outbound credential before direct dispatch.
- Bearer auth receives `Authorization: Bearer <token>`.
- Shared secret auth receives `x-nako-addon-secret: <token>`.
- Missing or unresolved secret references fail with the safe `authorization_gap` code.
- `crates/nako-server/src/http/tests/addons.rs` now covers bearer, shared-secret, and missing-secret direct-dispatch cases.

Validation:

- `cargo nextest run -p nako-server addon --no-fail-fast`
- `cargo nextest run -p nako-server addon_task_run_direct_dispatch_sends_bearer_token_from_host_secret_env addon_task_run_direct_dispatch_sends_shared_secret_from_host_secret_env addon_task_run_direct_dispatch_missing_host_secret_env_fails_safely --no-fail-fast`
- `cargo check -p nako-addon-client -p nako-server`
- `git diff --check`

Notes:

- The host still owns scheduling, retries, and result handling.
- The next lane is closeout or a split follow-on if a richer secret-provider abstraction is needed later.
