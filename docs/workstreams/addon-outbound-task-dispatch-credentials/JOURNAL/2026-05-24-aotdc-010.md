# AOTDC-010 Boundary Freeze

Date: 2026-05-24

The outbound task-dispatch credential follow-on is a separate lane from the
host-owned task runtime contract.

Current state:

- `crates/nako-addon-client/src/lib.rs` already knows how to emit `Authorization:
  Bearer` and `x-nako-addon-secret` headers when it is given a token.
- `crates/nako-server/src/app/addons/task_runtime.rs` currently calls
  `call_addon_task_with_outcome(..., None)` in the direct-dispatch path.
- The runtime contract lane explicitly split authenticated outbound task
  dispatch credential management as a follow-on.

Decision:

- Keep the host-owned task runtime boundary intact.
- Build a dedicated outbound credential storage/resolution lane.
- Do not widen this lane into Addon Manager, marketplace, package signing, or
  inbound Addon Token auth.
