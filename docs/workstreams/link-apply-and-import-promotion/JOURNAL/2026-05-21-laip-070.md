# LAIP-070 Journal — NFO Sidecar Mutation Split

Date: 2026-05-21
Task: LAIP-070
Status: Complete

## Decision

NFO sidecar import/export mutation is split to
`docs/workstreams/nfo-sidecar-promotion-apply`.

## Why

Managed Import promotion and NFO sidecar mutation are both protected writes, but
they protect different invariants:

- Managed Import promotion creates or verifies a **Media Source** target and
  commits catalog state after target durability.
- NFO export is a **Library File Write** that must preserve third-party NFO
  content through **NFO Round Trip**, backup existing files, and apply bounded
  retention/diagnostics.
- NFO import applies local metadata authority to canonical metadata, field
  locks, and possible **Hierarchy Confirmation**.
- Sidecar write/import partial failures need repair-pending or rollback
  semantics that are not the same as promotion target cleanup.

Keeping these in one lane would make promotion apply carry hidden metadata and
sidecar-write side effects. The safer boundary is an explicit follow-on lane
with its own audit and gates.

## Result

LAIP remains scoped to:

- accepted staged artifact promotion;
- VFS-mediated copy/hardlink/symlink target creation;
- catalog commit ordering after target durability;
- duplicate relationship persistence;
- cleanup-complete and cleanup-pending audit after promotion partial failure.

The NFO follow-on owns:

- sidecar apply acceptance and idempotent replay;
- current preview revalidation;
- backup, atomic replace, retention, rollback/repair diagnostics;
- local authority/field-lock/hierarchy application;
- redacted audit evidence.
