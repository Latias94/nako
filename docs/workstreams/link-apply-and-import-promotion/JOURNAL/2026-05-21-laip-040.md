# Link Apply And Import Promotion LAIP-040 — 2026-05-21

## Summary

Implemented VFS-mediated storage apply primitives for copy, hardlink, and
symlink targets. This slice only mutates storage through `StorageBackend::apply`;
it does not promote Media Sources or write catalog rows.

## Shipped

- Added `StorageApplyKind`, `StorageApplyRequest`, `StorageApplyStatus`,
  `StorageApplyObject`, and redacted `StorageApplyReport`.
- Added default unsupported `StorageBackend::apply` behavior.
- Forwarded apply through `Box`, `Arc`, and `CachedStorageBackend`.
- Implemented local copy apply with create-new semantics and cleanup after
  incomplete copy failure.
- Implemented local hardlink and symlink apply behind the same planning checks
  used by link dry-runs.
- Preserved no-overwrite, source-file, parent, and root-escape safety checks.
- Kept OS paths inside `taru-vfs`; reports return storage URIs, typed status,
  safe object metadata, and safe messages only.
