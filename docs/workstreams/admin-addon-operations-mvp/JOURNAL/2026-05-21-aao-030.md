# AAO-030 Journal — Unregister Semantics

Date: 2026-05-21

## Intent

Implement terminal Addon unregister semantics without physical deletion and
without expanding into Addon Manager process/package lifecycle.

## Implementation

- Added terminal `AddonStatus::Unregistered`.
- Added `POST /admin/v1/addons/{addon_id}/unregister`.
- Added `AddonRepository::unregister_addon_registration` with SQLite and
  PostgreSQL implementations.
- Unregister transitions the registration, revokes active Addon Tokens, and
  clears accepted grants in one backend operation.
- Registration, token, Side Effect, and Addon Artwork Candidate history remain
  retained for Admin audit/detail reads.
- Direct enable, token issue, token rotate, and grant replace against terminal
  registrations are rejected.
- Normal re-registration of a previously unregistered manifest creates a new
  disabled registration ID.
- Added active-manifest uniqueness so one active registration owns a manifest
  while terminal registrations remain retained.
- Kept `DELETE /admin/v1/addons/{addon_id}` unmounted.
