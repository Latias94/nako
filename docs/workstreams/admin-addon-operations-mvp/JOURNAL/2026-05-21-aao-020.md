# AAO-020 Journal — Lifecycle Mutation

Date: 2026-05-21

## Intent

Ship explicit Admin enable/disable mutation without using full Addon
registration upsert as a lifecycle command.

## Implementation

- Added `UpdateAddonStatusRequest` and `PATCH /admin/v1/addons/{addon_id}/status`.
- Added `AddonRepository::update_addon_registration_status` and implemented it
  for the Taru database facade, SQLite, and PostgreSQL.
- Added Admin service orchestration that revalidates the stored Addon Manifest
  snapshot and granted Addon Scopes before enabling.
- Kept `unregistered` out of AAO-020; unregister remains a separate AAO-030
  command.
- Changed runtime Addon principal resolution so disabled registrations fail
  before token `last_used_at` is refreshed.
- Added HTTP behavior coverage for disabled -> enabled -> disabled runtime
  access and redaction checks.
- Added SQLite and backend contract coverage for status mutation.

## Follow-up

Continue with AAO-030 unregister semantics: terminal `unregistered` state,
active token revocation, accepted grant clearing, audit preservation, and no
`DELETE /admin/v1/addons/{addon_id}` route.
