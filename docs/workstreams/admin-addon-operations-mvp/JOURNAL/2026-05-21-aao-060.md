# AAO-060 Journal — Resource-Call Diagnostics

Date: 2026-05-21

## Intent

Add a bounded Admin diagnostic route for declared Addon Resources so operators
can classify sidecar/resource failures without exposing diagnostic payloads,
response bodies, token material, storage details, or raw network errors.

## Implementation

- Added `AdminAddonResourceCallDiagnosticRequest`,
  `AdminAddonResourceCallDiagnosticResponse`, and
  `AdminAddonResourceCallDiagnosticStatus` to `taru-api::extension`.
- Added `POST /admin/v1/addons/{addon_id}/diagnostics/resource-call`.
- Added `taru-addon-client::call_addon_resource_with_outcome` so Admin
  diagnostics can report safe HTTP status and attempt count without exposing
  response payloads.
- Extended `AddonClientError::HttpStatus` with retryability metadata.
- Classified:
  - success;
  - missing resource declaration;
  - missing grant;
  - authorization gap;
  - unreachable transport;
  - protocol mismatch;
  - retryable HTTP failure;
  - non-retryable HTTP failure;
  - unsafe/invalid response.
- Added HTTP tests for successful diagnostics and safe failure classifications.
- Verified Admin responses do not echo diagnostic payloads, Addon response
  payloads, raw response bodies, Addon Tokens, Source Locators, storage paths,
  provider secrets, or raw network errors.
