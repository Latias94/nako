# AAO-040 Journal — Health Checks

Date: 2026-05-21

## Intent

Add a bounded, redaction-safe Admin Addon Health Check that proves Addon
Sidecar reachability and manifest compatibility without expanding into Addon
Manager process supervision.

## Implementation

- Added `AddonHealthCheckRequest`, `AddonHealthCheckResponse`,
  `AddonHealthStatus`, and `AddonHealthManifestFacts` to
  `taru-addon-protocol`.
- Added `validate_health_check_response` to verify protocol version, manifest
  ID, addon version, and resource count.
- Added `taru-addon-client::check_addon_health`, which calls
  `{manifest.base_url}/health` with protocol headers and a bounded timeout.
- Added reference-addon `/health` support.
- Added `AdminAddonHealthCheckResponse` and
  `AdminAddonHealthCheckStatus` to `taru-api::extension`.
- Added `POST /admin/v1/addons/{addon_id}/health-check`.
- Added HTTP coverage for a reachable sidecar and an unreachable sidecar.
- Health checks intentionally do not send administrator bearer tokens, Addon
  Tokens, resolved Secret Reference values, or resource payloads to the Addon
  Sidecar.
- Admin responses intentionally drop sidecar diagnostic payloads and raw
  network errors, returning safe classifications only.
