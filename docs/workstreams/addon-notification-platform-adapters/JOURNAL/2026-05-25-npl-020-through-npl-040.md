Implemented the first named platform adapter, `discord_webhook`, in
`nako-notification-bridge`.

Key decisions:

- `discord_webhook` is disabled by default.
- The provider is configured through
  `NAKO_NOTIFICATION_BRIDGE_DISCORD_WEBHOOK_*` sidecar env vars.
- Diagnostics expose only safe booleans/status strings.
- The outbound payload is Discord-compatible JSON with fixed text, event
  facts, and payload keys only.
- If both `http_webhook` and `discord_webhook` send paths are configured, the
  sidecar fails closed before sending to any provider to avoid duplicate
  partial fan-out under host retry.
