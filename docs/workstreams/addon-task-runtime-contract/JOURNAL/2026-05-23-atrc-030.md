# ATRC-030

## Summary

Implemented the first host-owned Addon Task runtime surface.

## Notes

- Added `AddonTaskRun` as a Nako-owned run record separate from manifest task
  declarations.
- Reused `JobKind::AddonTask` for scheduling, status, cancellation, and retry
  visibility.
- Added fenced sidecar worker updates using `run_token`.
- Added execution input to the runtime lease response so the sidecar can
  perform the declared task without exposing that payload in the admin summary.
- Added focused HTTP tests for success, failure retry, and cancellation
  acknowledgement.

## Validation

- `cargo check -p nako-api -p nako-server`
- `cargo nextest run -p nako-server addon_task_run --no-fail-fast`

# ATRC-040

## Summary

Added direct Addon Sidecar task-path dispatch on top of the same host-owned
Addon Task run model.

## Notes

- Added task request/response protocol envelopes and task response validation.
- Added an explicit `direct` dispatch mode while keeping `sidecar_claim` as the
  default for existing worker-claim behavior.
- Added client task-path calling with one HTTP dispatch per host-owned run.
- Added target `job_id` filtering to runtime claim so direct dispatch cannot
  claim another queued run for the same declaration.
- Added server direct dispatch handling for success, HTTP failure, direct retry
  inheritance, and in-flight host cancellation.
- Kept Addon Source Catalog discovery, declaration routing semantics, package
  signing, and process supervision out of this runtime slice.
- Authenticated outbound sidecar task dispatch still needs real credential
  storage; direct dispatch currently has coverage for `AddonAuth::None`.

## Validation

- `cargo check -p nako-api -p nako-server`
- `cargo nextest run -p nako-addon-client calls_declared_task_path_with_host_owned_run_envelope --no-fail-fast`
- `cargo nextest run -p nako-server addon_task_run_direct_dispatch --no-fail-fast`
- `cargo nextest run -p nako-server addon_task_run_ --no-fail-fast`
