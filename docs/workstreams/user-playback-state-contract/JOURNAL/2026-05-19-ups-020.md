# UPS-020 Journal

Date: 2026-05-19

## Claim

UPS-020 implements principal-aware **User Playback State** storage and
app-service behavior. Public protocol DTOs, HTTP routes, OpenAPI, SDKs, and
Android integration remain follow-on work.

## Changes

- Added `UserPrincipalId`, `UserPlaybackState`, and repository traits in
  `taru-core`.
- Added SQLite migration 0029 and `SqliteStore` persistence in `taru-db`.
- Added `UserPlaybackAppService` in `taru-server`.
- Added auth middleware resolution to `UserPrincipalId::local_admin()` for
  accepted bearer-token requests and explicitly disabled local/test auth.
- Covered principal isolation, Continue Watching filtering/sorting, default
  empty state, progress reporting, watched threshold policy, explicit
  watched/unwatched transitions, stale event rejection, and idempotent identical
  progress writes.

## Gates

- `cargo nextest run -p taru-db -p taru-server user_playback --no-fail-fast`
  passed.
- The original `user_playback_state` filter also passed, but it only matched
  two tests. The durable UPS-020 gate was corrected to `user_playback`.
