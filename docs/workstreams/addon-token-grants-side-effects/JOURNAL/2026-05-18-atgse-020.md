# 2026-05-18 ATGSE-020

Task: audit current addon token, grant, and side-effect boundaries.

## Summary

The current implementation supports M5 addon registration and outbound
Taru-to-Addon resource calls. It does not yet support addon-to-Taru identity,
token lifecycle, accepted grants, Library-Scoped Addon Grants, or Addon Side
Effect intake.

## Key Findings

- `AddonAuth` is outbound authentication for Taru calling an Addon Sidecar.
- `AddonRegistrationRecord.granted_scopes` is coarse registration state, not a
  token-bound accepted-grant model.
- `addon_registrations` has no token, grant, library scope, or side-effect
  tables.
- `/addons` is mounted behind the existing global inbound bearer middleware and
  should remain an admin/configuration surface.
- Public OpenAPI and TypeScript SDK tests intentionally exclude `/addons`.
- ADR 0020 already authorizes the intended direction; no ADR amendment is
  needed unless the next implementation changes strategy.

## Next Step

Run ATGSE-030. Add first-class Addon Token metadata and accepted-grant records
before implementing addon-principal runtime enforcement or side-effect intake.
