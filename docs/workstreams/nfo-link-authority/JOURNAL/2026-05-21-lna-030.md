# 2026-05-21 — LNA-030 Source Duplicate Link Evidence

## Goal

Route VFS link-plan diagnostics into `SourceDuplicateRelationship` evidence
without merging Media Sources or Media Items.

## Changes

- Added `CatalogAppService::record_filesystem_link_duplicate_suggestion`.
- Accepts only local VFS link plans whose status can be duplicate evidence:
  `Ready` or `TargetExists`.
- Validates the link plan's source/target storage URIs against the two Media
  Source locators before persisting evidence.
- Persists `FilesystemLink` evidence as `Suggested`.
- Stores only a redacted evidence string with storage scheme, link kind, and
  plan status; raw OS paths are not exposed.
- Added app tests that prove:
  - filesystem-link evidence is persisted;
  - source item links are not reassigned;
  - non-evidence link statuses do not insert duplicate relationships.

## Validation

```powershell
cargo nextest run -p taru-server filesystem_link_duplicate --no-fail-fast
cargo nextest run -p taru-server link_plan_status --no-fail-fast
cargo nextest run -p taru-server catalog --no-fail-fast
```

All final runs passed. The first red/green attempt failed because the test did
not persist the parent Library row, which correctly exposed the repository
foreign-key boundary.
