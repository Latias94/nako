# SDKRT-030 Journal — Rust Client Core Connection Tracer

Date: 2026-05-21
Status: DONE

## Scope

Implement the smallest no-socket Rust client core tracer for connection probing.
The core may construct protocol-level requests and interpret app-supplied
responses, but it must not own Android networking, token storage, UI, product
diagnostics, or Media3 behavior.

## Implementation

- Added `crates/nako-client-core`.
- Added FFI-safe data records for:
  - connection probe input;
  - HTTP headers, requests, responses, and safe request previews;
  - public error envelopes;
  - runtime failure kinds and failure details;
  - connection probe success and outcome states.
- Added `start_connection_probe` and `advance_connection_probe`.
- The tracer:
  - starts with unauthenticated `GET /health`;
  - requires a non-blank access token before the authenticated probe;
  - advances to `GET /libraries?limit=1&offset=0` with bearer auth after a
    compatible health response;
  - checks the public API-version header and health body version;
  - parses public error envelopes for non-2xx responses;
  - reports invalid health JSON as an invalid response;
  - redacts bearer tokens from safe request previews and public error messages.

## Validation

- `cargo fmt --package nako-client-core --package nako-client-uniffi --check`
  passed after the Rust core and UniFFI scaffold updates.
- `cargo nextest run -p nako-client-core --no-fail-fast` passed with 7 tests.

## Boundaries Preserved

- No Rust-owned sockets or Android transport were added.
- No Android profile persistence, token storage, cleartext/TLS policy, product
  diagnostics, UI, navigation, or Media3 behavior was moved.
- The first auth probe intentionally avoids strict library-list DTO decoding so
  the Kotlin forward-compatibility tolerance lane is not regressed by Rust enum
  strictness.
