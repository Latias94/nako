# SDKRT-020 Journal — ADR And FFI-Safe Core Contract

Date: 2026-05-21
Status: DONE

## Scope

Create ADR authority for pulling shared Rust client core forward and define the
first FFI-safe, no-socket runtime/core target before code.

## Decisions

- Added ADR 0032:
  `docs/adr/0032-shared-rust-client-core-app-supplied-transport.md`.
- Marked ADR 0031 superseded for post-generated-SDK mobile Rust/UniFFI
  sequencing.
- Chose a new no-socket `nako-client-core` crate as the first implementation
  target.
- Kept existing `nako-client` as the reqwest/async adapter that should later
  reuse `nako-client-core`.
- Deferred UniFFI scaffolding to a thin future `nako-client-uniffi` binding
  crate.
- Selected connection health plus authenticated library auth probe as the first
  tracer.

## First Tracer Shape

Rust core builds FFI-safe request specs and interprets FFI-safe response specs.
Android remains the HTTP executor and product diagnostic owner.

The first tracer may avoid library-list DTO decode and only inspect the auth
probe status/version/error envelope. That prevents strict Rust protocol enums
from regressing Android's generated Kotlin wire-value tolerance before Rust
tolerance is implemented.
