# SDKRT-040 Journal — Android UniFFI Connection Consumption

Date: 2026-05-21
Status: DONE

## Scope

Wire one Android connection flow to the Rust core / UniFFI binding boundary
without moving Android-owned platform or product responsibilities.

## Implementation

- Added `crates/taru-uniffi-bindgen` as a small repository-local wrapper around
  the pinned UniFFI CLI.
- Updated Android Gradle wiring to:
  - build the host `taru-client-uniffi` library before binding generation;
  - generate Kotlin bindings into `app/build/generated/source/uniffi/main/java`;
  - build Android ABI `libtaru_client_uniffi.so` outputs from Rust targets;
  - add generated Kotlin and JNI outputs to the Android main source set;
  - provide the host library override to JVM unit tests.
- Added Android's `RustConnectionCore` adapter around the generated UniFFI
  functions.
- Reworked `TaruConnectionClient` so Rust core / UniFFI owns:
  - connection probe request construction;
  - health/auth response interpretation;
  - API-version checks;
  - public error parsing;
  - redaction-safe request previews.
- Preserved Android ownership of:
  - base URL normalization;
  - cleartext/TLS policy;
  - HTTP transport execution and platform transport errors;
  - token and profile storage;
  - product failure categories and user messages;
  - UI, Compose, navigation, and Media3.

## Notes

The first focused Android test run exposed a Kotlin name-resolution trap:
`RustConnectionCore.startConnectionProbe` accidentally called itself instead of
the generated UniFFI top-level function. The adapter now calls the generated
functions with fully-qualified names.
