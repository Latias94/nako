# SDKRT-010 Journal — Runtime Ownership Freeze

Date: 2026-05-21
Status: DONE

## Scope

Inventory current SDK/runtime/app/Rust-client responsibilities and freeze the
runtime ownership direction before implementation.

## Evidence Reviewed

- Android `PublicClientApiExecutor` owns request execution semantics, public
  error parsing, API-version checks, invalid response mapping, transport failure
  mapping, and redaction.
- Android `NakoHttpTransport` / `JdkNakoHttpTransport` own platform HTTP
  execution and cleartext policy integration.
- Generated Kotlin SDK owns route descriptors, API constants, DTOs, and tolerant
  public string wrappers.
- `nako-client` already owns Rust-side route/request construction, public error
  parsing, version checks, streaming request builders, and reqwest execution.
- `nako-client` is not FFI-safe as-is because it exposes reqwest, URL/header
  types, async traits, and reqwest errors.
- `nako-client-protocol` still has strict serde enums for additive public wire
  values, which would regress Android's new generated SDK tolerance if Rust
  immediately owned mobile decode.

## Decision

Select early shared Rust client core / UniFFI target state.

The first tracer should use app-supplied Android transport. Rust should build
FFI-safe request specs and interpret response specs. Android should continue to
own cleartext/TLS policy, token storage, profile persistence, product
diagnostics, UI copy, Compose/navigation, and Media3.

## ADR Impact

ADR 0031's mobile-FFI sequencing must be amended or superseded. `SDKRT-020`
should create the target-state ADR and define crate/API/build topology before
runtime code starts.
