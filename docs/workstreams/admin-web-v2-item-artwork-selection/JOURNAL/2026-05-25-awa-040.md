# AWA-040 Artwork Gallery UI

Date: 2026-05-25

## Claim

The item artwork gallery has a read-only Admin Web route with safe
data-source projection and deterministic fallback.

## Changes

- Added `AdminDataSource.loadItemArtworkGallery` and mapped
  `AdminManagedArtworkGalleryResponse` into route-local summaries.
- Added deterministic mock gallery data for fallback and tests.
- Added `/items/:itemId/artwork` with URL-owned limit/offset pagination.
- Linked Media Item detail to the artwork gallery route.
- Rendered candidate, Managed Artwork artifact, and Selected Artwork summaries
  without select/unpublish mutation controls.
- Guarded image rendering to first-party `/images/...` routes.

## Verification

- TDD red: `npm run test -- adminApi/dataSource.test.ts` failed before
  implementation because `loadItemArtworkGallery` was missing.
- TDD red: `npm run test -- App.test.tsx` failed before implementation with
  route-level Not Found for `/items/:itemId/artwork`.
- `npm run test -- adminApi/dataSource.test.ts` passed: 23 tests.
- `npm run test -- App.test.tsx` passed: 64 tests.
- `npm run check` passed.
- `npm run test -- App.test.tsx adminApi/dataSource.test.ts` passed: 87 tests.
- Browser smoke passed on
  `http://127.0.0.1:5176/items/item-unknown-1/artwork?limit=20&offset=0`
  in desktop and 390x844 mobile viewports: rendered fallback gallery, no
  console errors, no horizontal overflow, and no unsafe artwork
  source/storage/cache/path/hash/token text.

## Handoff

AWA-050 can add select/replace and unpublish controls, but only behind
explicit confirmation and visible mutation failure states. Mutation fallback
must not report fake success.
