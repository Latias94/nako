# MRS-030 MVP Gate Plan

Date: 2026-06-01
Status: DONE_WITH_CONCERNS

## Goal

Turn the verified MVP release cut into a validation ladder that can be run on a
release candidate.

## Result

`EVIDENCE_AND_GATES.md` now defines the MVP ladder:

- Gate 0: planner/docs/redaction preflight.
- Gate 1: existing `scripts/release-gate.ps1 -Mode fast`.
- Gate 2: focused server MVP journey tests for startup, scan, metadata,
  storage, addons, playback/HLS, and playback state.
- Gate 3: Web/Public Client tests and live browser smoke expectations.
- Gate 4: `PTJCH-220` playback runtime closeout.
- Gate 5: package and container shape.
- Gate 6: official addon alpha smoke.
- Gate 7: conditional PostgreSQL compatibility.

## Routing Decisions

- `PTJCH-220` remains a P0 blocker.
- Web/Public Client live smoke is a P0 gate gap if existing tests plus manual
  browser smoke are not reproducible enough for release.
- A one-command wrapper for the full video-first ladder is useful but should be
  split to `operations-release` only after the team decides it is required.
- `GAMA-060` remains conditional/P1 unless MVP exposes Web Generated Artifact
  apply.
- `CSAPA-050` remains P1/deferred while browser/web is the accepted MVP client
  path.
- Vendor hardware matrix, watcher/debounce, realtime, large-library cache/ETag,
  and desktop/native clients stay post-MVP unless a gate failure escalates them.
