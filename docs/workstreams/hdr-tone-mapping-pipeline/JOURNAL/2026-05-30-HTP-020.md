## Behavior Covered

- HDR10/PQ source on an SDR-only client produces `tone_mapping=required`.
- HLG/HDR source on an HDR-capable client preserves source color when transcode
  is explicitly requested.
- Dynamic HDR paths such as Dolby Vision are marked
  `deferred_unsupported` for this playback-only slice.
- Unsupported-container HDR sources on SDR-only clients select transcode, not
  remux, so remux cannot bypass HDR-to-SDR tone mapping intent.

## Reviewer Finding Follow-Up

The first implementation left `evaluate_remux` treating HDR as always
supported. That allowed an SDR-only client to remux an HDR source when the
source container was unsupported. The regression test reproduced the issue with
an HDR MKV source and an SDR-only client. The fix makes remux compatibility use
the target profile's HDR support, because remux cannot change color range or
perform tone mapping.
