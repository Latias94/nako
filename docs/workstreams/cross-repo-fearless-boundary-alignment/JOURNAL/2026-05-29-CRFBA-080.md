# CRFBA-080 Playback Runtime Transcode Ownership

Date: 2026-05-29

## Summary

Deepened the Playback Runtime boundary so product-level transcode session state
is no longer owned by `nako-transcode`. The transcode crate now exposes
immutable `TranscodeExecutionRequest` values and typed engine outcomes. The
FFmpeg HLS/Remux runners execute those requests and return artifact, metrics,
and cancellation results without mutating a local product session manager.

`nako-server` remains the product owner for persisted session lifecycle:
admission/reuse, cancellation registration, failure taxonomy, state
transitions, finished events, and HLS runtime metrics persistence all stay in
the playback runtime layer.

## Deleted Surface

- Removed `TranscodeSessionManager` and its in-memory product state transitions
  from the public `nako-transcode` API.
- Removed `TranscodeEngineAdapter::progress`, which reported product session
  state from the lower-level engine adapter.
- Removed local HLS/Remux manager creation in server playback runtime paths.

## Validation

- `cargo nextest run -p nako-transcode` passed 73 tests.

- `cargo nextest run -p nako-server app::tests::playback` passed 35 tests.
- `cargo nextest run -p nako-playback` passed 19 tests.
