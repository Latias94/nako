# CRFBA-020 Journal - 2026-05-24

## Summary

Added a narrow addon registration/grant store port in `crates/nako-server`.

## What Changed

- `AddonAppService` still keeps `NakoDatabase` for the broader addon workflow.
- Addon registration, status, and grant operations now go through a dedicated
  `AddonRegistrationStore` port.
- The port is intentionally smaller than the full database facade and only
  covers the workflow-shaped operations this slice needs.

## NFO Workflow Store

Narrowed `crates/nako-server/src/app/nfo.rs` behind a dedicated
`NfoWorkflowStore` so app-level NFO job creation, library/source/item lookups,
sidecar-apply audit state transitions, outbox writes, and durable job runtime
lease handoff no longer reach directly through the broad database facade.

`NfoService` still receives the concrete repository handle for import/export
domain execution because that crate already has its own repository trait
requirements for metadata, catalog, search, and NFO persistence behavior.

## Metadata Execution Follow-Up

Deepened `crates/nako-server/src/app/metadata.rs` so direct workflow reads and
writes stay on `MetadataWorkflowStore` while catalog hydration, refresh
snapshot/commit, and attempt recording move through `MetadataExecutionStore`.
`crates/nako-metadata/src/lib.rs` now re-exports `MetadataAttemptPort`,
`MetadataRefreshPort`, `MetadataRefreshCommit`, and `MetadataRefreshSnapshot`
for that narrower execution store.

## Library Scan Follow-Up

Deepened `crates/nako-server/src/app/jobs.rs` so library scan enqueue,
library lookup, outbox writes, scan ingestion, probe execution, and
ingestion-failure bookkeeping move through `LibraryScanWorkflowStore` and
`LibraryScanExecutionStore`. `crates/nako-library/src/probe.rs` now depends on
`LibraryProbeWorkflow`, and the focused library tests were updated to call the
intended repository trait explicitly where the method names overlap.

## Playback Runtime Follow-Up

Deepened `crates/nako-server/src/app/playback/mod.rs` so playback decisions,
remux/HLS execution, transcode-session access, cancellation, and
finished-event writes move through `PlaybackRuntimeStore` instead of the broad
database facade.

## Playback Staging Follow-Up

Deepened `crates/nako-server/src/app/playback/input.rs` and
`crates/nako-server/src/app/staging.rs` so staging manifest lookup and lease
acquisition now use `Arc<dyn StagingManifestRepository>` instead of the raw
database facade. `PlaybackAppService::new` now receives runtime/staging ports
from composition, keeping `NakoDatabase` at the wiring layer.
